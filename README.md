# 纸上打飞机 · 联机版

小时候课间在纸上玩的那个游戏 —— 10×10 方格、每方三架 1513 形飞机、喊号打中机头才算击落。

它现在是**飞牛 fnOS 上的一个应用**：Go 单二进制后端 + 原生前端（无框架、无第三方依赖），
支持邀请对局、房间码、断线重连、观战、再来一局，并区分「飞牛网关」与「独立端口」两种入口。

![status](https://img.shields.io/badge/version-0.9.4-blue) ![go](https://img.shields.io/badge/Go-1.27-00ADD8) ![license](https://img.shields.io/badge/license-MIT-green)

## 特性

- **规则**：10×10 棋盘，每方三架飞机（各 10 格），机头命中即击落，三架全灭判胜
- **可选规则**：交替出手 / 打中连击、死机残格「骗人」、每回合 3 或 5 分钟
- **对局**：邀请、房间码加入、满员自动旁观、结束后再来一局
- **容错**：断线 2 分钟内重连接管座位，超时判负；回合超时给出明确原因
- **入口**：飞牛统一网关（身份固定「管理员」）/ 独立端口（游客自动昵称）/ 本机回环管理口
- **界面**：PC / 平板 / 手机自适应，纸质棋盘风格
## 本地运行

```bash
go build -o bin/server.exe ./cmd/server
./bin/server.exe -data ./data
```

启动后日志会打印：

```
[管理] 本机入口 http://127.0.0.1:8081（仅回环地址）
[端口] 对外访问已关闭（仅飞牛网关可用）
管理口令（设置面板/调试用）: xxxxx
```

浏览器打开 <http://127.0.0.1:8081> 即可（热座演示：随机布阵 → 轮流点击对方棋盘）。

> 端口默认是关闭的：只有回环管理入口 + （部署在 fnOS 上时的）统一网关可用。
> 想对局域网/外网开放，就去「设置面板」填管理口令、勾选「允许独立端口对外访问」。

## 三个入口

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 管理（始终开启） | `127.0.0.1:8081` | 仅回环。端口关闭、网关故障时的恢复入口 |
| 独立端口（受开关控制） | `0.0.0.0:<public_port>` | 默认关闭，可在设置面板热开启/关闭 |
| 飞牛统一网关 | `/${gateway-prefix}`，默认 `/app/planeduel` | 需要 `TRIM_APPDEST`，监听 `$TRIM_APPDEST/app.sock` |

同一份路由同时兼容两种路径：`/api/x` 与 `/app/planeduel/api/x`。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/healthz` | 健康检查 |
| GET | `/api/session` | 当前游客身份 |
| POST | `/api/session` | `{"nick":"小明"}` 占用昵称（全局唯一，重复返回 409） |
| GET | `/api/players` | 在线玩家列表：`[{nick, online, idle_sec, me}]` |
| GET | `/api/admin/settings` | 需 `X-Admin-Token` 或网关注入的 `X-Trim-Isadmin: true` |
| PUT | `/api/admin/settings` | `{"public_port_enabled":true,"public_port":18080}` 热开关端口 |
| POST | `/api/solo` | 开一局单人视角对局（随机布阵，对手为随机陪练） |
| POST | `/api/solo/fire` | `{"id":"...","cell":"C5"}` 喊号；返回我方的完整视角 |

### 视角约定（与纸面对战纸一致）

- 左「布阵图」：自己的 30 格飞机 + 对手打在我棋盘上的结果；
- 右「敌情图」：**开局全空白**，只记录我打出的 ○ 空 / × 中 / ◎ 死；
- 服务端只下发自己的棋盘和「我打过的格子」，永不下发对手布阵；
- 陪练强度按人类水平调过（纯随机，测试里双方约各 75 发决出胜负）。

### 三个入口的身份差异（重要）

| 入口 | 通道 | 昵称 | 设置面板 | 管理接口 |
| --- | --- | --- | --- | --- |
| 飞牛网关 `/app/planeduel/` | `gateway` | **自动取 NAS 账号**（如 `laok`），无需输入 | 显示；管理员可直接改 | 允许（管理员） |
| 本机回环 `127.0.0.1:18088` | `admin` | 无 | 显示 | 允许（需口令） |
| 独立端口 `:28082` | `port` | 需手动起昵称 | **不显示** | **一律 403** |

端口通道会忽略客户端伪造的 `X-Trim-Username` / `X-Trim-Isadmin`，所以外人无法借此冒充管理员。
热开端口时也复用同一个通道处理器（否则会退化成裸 handler —— 这个 bug 有回归测试盯着）。

### 三端适配

| 断点 | 布局 | 格子 |
| --- | --- | --- |
| ≥1100px（PC） | 左右两栏：对战纸 + 侧栏 | 32px |
| 720–1100px（平板） | 单栏，侧栏三卡横排 | 29px |
| <720px（手机） | 两盘上下排列，标题条压缩 | `clamp(22px, (100vw-62px)/11, 30px)` |

## 规范

- 坐标：行 A–J（纵）× 列 1–10（横），JSON 里统一用 `"C5"` 这种写法。
- 昵称：2–12 个字符，仅中英文/数字/`_`/`-`；大小写与首尾空格归一化后判重；保留词（admin/系统…）不可用；30 天不活跃自动释放。

### 重新打包 / 升级流程

```bash
# 1) 本地交叉编译（Linux amd64，无 CGO）
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  go build -trimpath -ldflags "-s -w" -o dist/planeduel-server ./cmd/server

# 2) 拷进包目录
cp dist/planeduel-server dist/pkg/planeduel/app/planeduel/

# 3) 生成图标（可选，改了设计才需要）
python dist/gen_icon.py

# 4) 打包上传后在 NAS 上构建
tar -czf dist/pkg.tar.gz -C dist/pkg planeduel
pscp -P 5022 dist/pkg.tar.gz <用户名>@<你的NAS>:/home/laok/
# NAS 上：
cd ~ && rm -rf planeduel && tar -xzf pd-pkg.tar.gz
chmod +x planeduel/cmd/* planeduel/app/planeduel/planeduel-server
cd planeduel && fnpack build

# 5) 升级安装（保留数据目录）
sudo appcenter-cli install-fpk /home/laok/planeduel/planeduel.fpk
```

升级要改 `manifest` 里的 `version`；`upgrade_*` 脚本会先停后启，`var/` 下的数据不动。

### ⚠️ 升级的坑（实测）

| 命令 | 行为 |
| --- | --- |
| `install-fpk <fpk>` | **应用已存在时直接短路**，只打印 `Application [planeduel] is installed.`，不升级 |
| `install-local -d <dir>` | 会**先卸载再安装**，然后在这台机器上报 `code 10237`，结果应用被卸掉 |
| 应用中心「手动安装」选 fpk | 正常识别为升级（推荐） |

所以升级流程是：**本地 `fnpack build` → 把 fpk 拷到 NAS → 在飞牛网页端「应用中心 → 手动安装」选择该 fpk**。
若走 CLI，只能先 `uninstall` 再 `install-fpk`（会丢失 `config.json` 与昵称数据）。

### 在飞牛上踩到的坑（记下来省得再踩）

1. **`gatewayPrefix` 不能带点号**：`/app/fnos.sudoku` 会被网关注册校验拒绝，必须像 `/app/planeduel` 这样无点号。
2. **`os_min_version` 要写成 `1.1.3100`** 这种真版本号格式，写 `1.1.31` 会被拒。
3. **`cmd/main` 不在 `TRIM_APPDEST` 下**，脚本里要用自己所在目录去定位包内文件。
4. 应用以 `run-as: package` 的用户运行，`TRIM_APPDEST` 下的 socket 才会被网关接受。
5. 端口默认必须关闭：否则 `checkport` / 端口占用会干扰安装；本应用改由面板控制（`checkport=false`）。


## 邀请对战（0.4.x）

### 玩法

1. 双方各自打开页面（网关或 `:28082` 都行），先有昵称 —— 网关进来会自动用 NAS 账号；
2. 在「在线玩家」里找到对方，点昵称右边的 **邀请游戏**；
3. 对方页面弹出邀请框，点 **接受** 即开局（双方随机布阵，邀请方先手）；
4. 轮流点右侧敌情图喊号，打空换人、打中连击（沿用房间规则）；
5. 结束显示胜负，点「离开房间」回大厅。

也可以用房间码：一方点 **建房** 拿到 6 位码，另一方在「房间码」框里输入加入。

### 实时协议（WebSocket `/ws`）

自实现 RFC 6455（握手 + 文本帧 + ping/pong/close），不依赖第三方库（NAS 上拉不到 module）。

| 方向 | 消息 | 说明 |
| --- | --- | --- |
| C→S | `{"t":"invite","to":"昵称"}` | 邀请某人 |
| C→S | `{"t":"invite.reply","id":"…","accept":true}` | 接受/拒绝 |
| C→S | `{"t":"room.create"}` / `{"t":"room.join","code":"ABC123"}` | 建房 / 按码加入 |
| C→S | `{"t":"shot","cell":"C5"}` | 喊号 |
| C→S | `{"t":"room.leave"}` / `{"t":"ping"}` | 离开 / 心跳 |
| S→C | `{"t":"players","list":[…]}` | 在线列表（含 `busy` 表示对局中） |
| S→C | `{"t":"invite","id":"…","from":"昵称"}` | 收到邀请 |
| S→C | `{"t":"room","room":{…}}` | 房间状态 + **各自视角**的棋盘 |
| S→C | `{"t":"error","msg":"…"}` / `{"t":"timeout","winner":0}` | 错误 / 超时 |

### 规则与限制

| 项 | 值 |
| --- | --- |
| 邀请有效期 | 20 秒 |
| 回合时限 | 90 秒，超时判当前出手方负 |
| 掉线 | 直接判负（避免房间卡死） |
| 布阵 | 当前为服务端随机布阵（手动摆阵后续加） |
| 同一昵称多开 | 新连接会踢掉旧连接 |

### 测试覆盖

`go test ./...` 共 14 个用例，其中对战链路包括：

### 常见问题：同一台电脑想开两个玩家

0.4.3 起每个浏览器标签各自持有身份（token 存 `sessionStorage`），所以：

1. 窗口 1 正常进入（网关下自动是 NAS 账号，如 `laok`）；
2. 窗口 2 点顶部「改名」换成别的昵称（如 `laok2`）；
3. 两个窗口就各自是独立玩家，可以互相邀请。

如果两个窗口用的是同一个身份，第二个窗口会提示「这个身份已经在另一个窗口打开了」并停止重连，改名后自动恢复。

### 断线与超时（0.4.3）

| 情况 | 行为 |
| --- | --- |
| WebSocket 断开 | 房间保持 playing，**45 秒**宽限；重连（同一身份）自动接管座位、继续打 |
| 超过 45 秒没回来 | 判掉线方负 |
| 一回合超过 90 秒 | 判当前出手方负 |
| 主动点「离开房间」 | 按认输处理 |

> 这些是 0.4.2 修复的重点：之前**断线立即判负**，而前端每 2.5 秒会自动重连，
> 于是出现「刚开打就无效」——重连把房间判结束了。现在重连是接管而不是判负。
### 对局"突然结束"的排查（0.4.4）

规则层面已用测试锁死：**只打机身/机翅/机尾（27 格）既不会击落也不会结束**，
只有机头命中才 `Dead`，三架都 Dead 才判胜（`TestNoWinWithoutHeadShot`）。

所以对局结束只可能是下面几种，界面上现在会**明确写出原因**：

| 结束提示 | 含义 |
| --- | --- |
| 🏆 你赢了（三架飞机全部被击落） | 正常胜利 |
| 你输了（三架飞机全部被击落） | 正常失败 |
| …（回合超时） | 该出手的一方 180 秒没喊号 |
| …（掉线超过宽限） | 掉线 120 秒未重连 |
| …（对手主动离开） | 对方点了「离开房间」 |

时限在 0.4.4 放宽：回合 90s → **180s**，掉线宽限 45s → **120s**，
界面显示「本回合剩余 Xs」，最后 20 秒变黄。
### 回合时限（0.4.5）

- 建房/邀请前可在界面上选 **3 分钟** 或 **5 分钟**（默认 5 分钟）；
- **每打一发都会重新计时**：换手后对手拿到的也是完整时限，连击时也一样；
- 界面显示「本回合剩余 Xs」，最后 20 秒变黄；
- 超过时限判当前出手方负，结束提示会写明「回合超时」。
### 出手规则（0.5.0）

建房/邀请前可选：

| 选项 | 行为 |
| --- | --- |
| **交替出手（默认）** | 每打一发就换人，双方机会完全均匀 |
| 打中连击 | 打中（中/死）继续出手，打空才换人 —— 这是纸面游戏的老玩法 |

默认改成「交替出手」是因为：旧版默认连击，一方连中时会连续出手很多发，
对面看起来就像"只有一方能打"。想要老规则可在建房时选「打中连击」。

另外，点非自己回合的格子现在会提示「还没轮到你 —— 现在轮到 X」，不再静默。

新增 `rules_audit_test.go`，用**独立于引擎实现**的方式校验规则：

| 测试 | 校验内容 |

| --- | --- | --- |

## 房间码（0.6.1 修复）

之前「加入房间」失败的原因有两个，都是实现 bug：

1. 房间码生成了 **8 位**，而输入框 `maxlength=6` → 永远输不全；
2. 码里含大小写与 `-`/`_`，前端做了 `toUpperCase`，服务端又是区分大小写的比较 → 对不上。

修复：码固定 **6 位**、字母表去掉易混的 `0 O 1 I L`（只剩 `A-Z 2-9`），服务端比较时忽略大小写与空格。
实测：`UMVBKR` → 输入 `umvbkr` 可正常加入并开局。
## 观战模式（0.7.x）

第 3 个人以后不再被拒之门外：

1. 在「房间码」框里填两位玩家的房间码；
2. 点 **旁观**（不是「加入」）；
3. 页面切到观战视角：左盘是甲的棋盘、右盘是乙的棋盘。

### 能看到什么

### 网关身份（0.7.3，修正）

这里之前有个实现错误，记下来避免回退：

- **错误做法**：把显示名写成「管理员」，但身份键仍用 `X-Trim-Username`（`EnsureAdmin("fnos:" + name)`）。
  后果有两个：仍然在识别飞牛账号；而且网关一旦不注入这个头，自动登录**直接失效**。
- **现在的做法**：`gateway` 通道 = 固定身份「管理员」，代码里不再读取 `X-Trim-Username`；
  权限也一并固定（`gateway` 即管理员，不依赖 `X-Trim-Isadmin`，否则面板可能因为头缺失而不显示）。
- **锁死回归**：`TestGatewayIgnoresFnosUsernameHeader`（伪造用户名头也仍是管理员）、
  `TestGatewayNicknameIsAdmin`（一个头都不带）、`TestGatewayCanRename`（改名不被重置）。

自动化验证（不带任何飞牛头）：


## 在线列表为什么看不到「管理员」（0.8.2）

两个原因，第二个是 bug：

1. **在线 = 当前打开着页面**。列表来自 WebSocket 连接集合，
   管理员只有在飞牛网关页面开着的时候才在线；关掉页面就消失了（不是常驻名额）。
2. **Cookie 跨端口串号（已修）**。旧版 Cookie 名统一是 `pd_sid`、`Path=/`，
   而 HTTP Cookie **不区分端口**：只要在网关打开过一次，再访问 `:28082` 就会带上同一个
   `pd_sid`，于是端口页面**直接继承了「管理员」身份**。两个页面共用一个 token →
   互相顶号（后连的把先连的踢掉），表现就是「管理员从列表里消失了」。

修复：Cookie 按通道隔离。

| 通道 | Cookie |
| --- | --- |
| 飞牛网关 | `pd_sid_gw` |
| 独立端口 | `pd_sid_port` |
| 本机管理入口 | `pd_sid` |

实测：

```
网关:            {"nick":"管理员","channel":"gateway"}  Set-Cookie: pd_sid_gw=...
端口带 pd_sid_gw: {"authenticated":false,"channel":"port"}      ← 不再继承管理员
端口自动分配:     {"nick":"打飞机","nick":"打飞机"}              Set-Cookie: pd_sid_port=...
```

## 「接受邀请后不能开局」（0.8.3 修复）

现象：能收到邀请弹窗，点「接受」后没有反应。

原因：上一局打完后，房间进入 `done`，但双方客户端仍挂在房里（如果没点「离开房间」）。
服务端在邀请/接受时检查 `c.room != nil`，于是直接回「你或对方正在对局中」，
邀请被丢弃，新局自然开不起来。错误只显示在灰色小字里，很容易被忽略。

修复：新增 `freeIfDoneLocked`，在**邀请 / 接受邀请 / 建房 / 加入**之前，
把「已结束（state != playing）」的房间占位释放掉：

- `state == "playing"` 时**绝不释放**（不会打断正在进行的对局）；
- 两块座位都空了的房间直接删除。

回归测试：`TestInviteAgainAfterGameEnds`（打完一局 → 不点离开 → 再邀请 → 能正常开局）。

实机验证：

```
第一局结束: state=done reason=win winner=0
不点离开，直接再邀请 → 第二局 state=playing 房间码=RN2JDB  ✅
```

另外错误提示现在会以红色显示在「对局」卡片底部，不再藏在灰色小字里。

## 重连（0.9.2，之前是假的）

之前的实现有两个问题：

1. **状态标签样式丢失**：`setConn` 里写的是 `el.className = 'conn'`，而 CSS 里叫 `.chip`，
   所以那行字是没有样式的裸文本，看起来就不像"正在重连"。
2. **重连既无倒计时也无次数**：只有一个写死的 `setTimeout(connectWS, 2500)`，
   界面上永远是同一句「连接中断，正在重连…」；失败也不会有任何变化，像是卡住了。
   而且 `connectWS` 在没昵称时直接 `return`，连尝试都不会发生。

现在的行为：

```
连接中断，10s 后重连（第 1 次）   ← 每秒递减
连接中断，9s 后重连（第 1 次）
…
正在重连…（第 1 次）             ← 倒计时归零，真的建立连接
已连接                           ← 成功后标签变绿，计数清零
```

- 断线时顶栏出现 **立即重连** 按钮，点了马上重连（不用等满 10 秒）
- 每次尝试都会累加次数，连续失败也能看出在重试
- 同一身份在别的窗口打开时，显示「这个身份已在别的窗口」且**不**自动重连（避免两边互相踢）

验证方式：用假时钟驱动 `scheduleReconnect`（`reconnect_test.js`），

```
倒计时序列: 9s 8s 7s 6s 5s 4s 3s 2s 1s
第 10 秒后: 正在连接…     WebSocket 创建次数: 2（首次 + 重连一次）
点「立即重连」→ 新建 1 个连接
连续失败 → 提示「第 5 次」
```

## 构建与打包

所有构建动作都收在 `Makefile` 里，CI 也直接调它（避免本地和 CI 两套命令走偏）：

```bash
make test     # 跑全部单测
make build    # 交叉编译 linux/amd64 服务端到打包目录
make pack     # 打包 .fpk（首次会自动下载 fnpack 1.2.3）
make all      # test + pack
make run      # 本地跑起来（管理口 http://127.0.0.1:18088）
make clean    # 清理产物
```

产物：`dist/planeduel_x86_v<版本>.fpk`，同时生成 `.sha256`。

### GitHub Actions

`.github/workflows/build-fpk.yml`：

| 触发 | 行为 |
| --- | --- |
| push 到 `main` | 跑 `go vet` + `make test`，通过后打包并上传 artifact（保留 14 天） |
| push tag `v*` | 额外把 fpk 与 sha256 发布到 Release |
| 手动运行（workflow_dispatch） | 可指定版本号，留空则用 manifest 里的版本 |

打包前会做一次行尾归一（`sed -i 's/\r$//'`），避免 Windows 上提交的 CRLF 让 `cmd/*` 脚本在飞牛里跑不起来；
仓库同时用 `.gitattributes` 固定这些文件的 LF 存储。

> 需要 arm64 安装包时：manifest 的 `platform` 改为 `all`，并在 `make build` 里加一条 `GOARCH=arm64` 的构建即可（当前只出 x86_64）。
